Depth testing
-------------
* A depth buffer prevents triangles from rendering in front of 
when they should be behind. 
    * OpenGL tests the depth val of a frag against the
    content stored in the depth buffer.
    * Successful test: Fragment is rendered and buffer is updated
    * Failed test: Fragment is discarded
* Stores information per fragment
* Most systems have depth buffer with a precision of 24 bits
    * 16, 24, and 32 bit depth values exist
* Depth testing is done after the fragment shader and stencil test
    * gl_FragCoord is accessible and defined by glViewport
        * screen-space coordinated ([0,0] is bottom left corner)
        * the z-component is the depth value and is used to
        compate the depth buffer's content
    * Early depth testing is done before the fragment shader
    and a depth value should not be written.
        * Useful for when fragments will clearly not be seen.
* Depth testing is enabled by glEnable(GL_DEPTH_TEST);
    * OpenGL will automatically store the z-values if passed
    and not if failed
    * As we clear the color buffer, we should clear the depth 
    buffer, or we will be stuck with the previous frame values
    * Scenarios where we want to depth test all fragments, 
    discard accordingly, and not update the buffer.
        * We create a temporary read-only buffer
        * OpenGL allows this through glDepthMask(GL_FALSE);
* We can control in what way the depth test compares by
changing the depth function
    * glDepthFunc(funct_name) changes the comparison op. used
        * GL_ALWAYS   - always pass depth test
            * Last rendered fragment will show in front
        * GL_NEVER    - never pass depth test
        * GL_LESS     - pass if frag depth < stored depth val
            * Default
        * GL_EQUAL    - pass if frag depth == stored depth val
        * GL_LEQUAL   - pass if frag depth <= stored depth val
        * GL_GREATER  - pass if frag depth > stored depth val
        * GL_NOTEQUAL - pass if frag depth != stored depth val
        * GL_GEQUAL   - pass if frag depth >= stored depth val
* Depth value precision
    * The buffer contains vals from 0.0 to 1.0
    * All z-values of objects are compared with buffer content
        * As seen from viewer
        * Can be any value between projection-frustrum's 
        near and far plane
            * We need to normalize these values
            * A linear transform is used to convert to depth
            vals
                * dVal = (z - near)/(far - near)
                    * z is value within frustrum
                    * near and far are part of proj. matrix
                * Almost never used
            * A non-linear depth equation is primarily used
                * dVal = [(1/z) - (1/near)]/[(1/far) - (1/near)] 
                * A lot of precision close up
                * Much less precision far away
                * Depth buffer values are not linear in clip-space
                    * linear in view space before proj. mat.
* Z-fighting
    * A common problem where fragments are rendering in the
    exact same location. In this scenario, the depth buffer
    is unable to decide which fragment to render in front.
    Thus, the fragments fight for visibility.
        * Techniques to prevent this
            * Do not put fragments at the same location with
            a very small variation that will be unnoticeable
                * Hard to do for every objects
            * Make the near plane very far away
            * Increase depth buffer precision
                * costs performance

Stencil testing
---------------
* A stencil buffer is another buffer used to discard fragments
    * Done before depth test
    * Each pixel has a total amount of 256 different stencil values
    * By changing the specific values in the stencil buffer,
    we are effectively writing to it in order to read whether we
    will discard or pass fragments.
    * A general use case is as follows:
        * Enable
        * Render and update contents
        * Disable
        * Render and discard fragments based on contents
            * We can discard fragments based on fragments
            from other scenes
    * glEnable(GL_STENCIL_TEST) will enable it
    * We will also need to clear GL_STENCIL_BUFFER_BIT
    * glStencilMask(0xFF or 0x00) are write or not write, respectively
        * 0xFF and 0x00 are bitmasks
* Stencil functions
    * glStencilFunc(GLenum func, GLint ref, GLuint mask)
        * func is the comparison operator (see depth testing)
        * ref is the value we are comparing to
        * mask is ANDed with both ref and stencil value before test
            * Ex: glStencilFunc(GL_EQUAL, 1, 0xFF)
                * when stencil value is equal to 1, frag passes
    * glStencilOp(GLenum sfail, GLenum dpfail, GLenum dppass)
        * sfail  - action if stencil test fails
        * dpfail - action if stencil test passes, but depth fails
        * dppass - action if both tests pass
            * Actions: 
                * GL_KEEP      - current stencil val is kept
                * GL_ZERO      - stencil val is set to 0
                * GL_REPLACE   - replaced with ref
                * GL_INCR      - stencil val ++1 if lower than max
                * GL_INCR_WRAP - same as above, but is 0 if > max
                * GL_DECR      - stencil val --1 if higher than min
                * GL_DECR_WRAP - same as above, but if max if < 0
                * GL_INVERT    - inverts current stencil buffer val
* Uses
    * A great and common uses for stencil testing is outlining
    objects when they are selected.
    * Can also draw textures in mirrors
    * Rendering real-time shadows in shadow volumes
    * and more!

Advanced Lighting
-----------------
* When using the phong lighting model, if the viewing angle is
greater than 90 degrees, the specular shine breaks down and
looks unnatural. This happens when the light source is close
to the lit surface. An opposite reflection ray is produced
on the other side of the normal vector. We use the reflection
vector to calculate the specular lighting and if the specular
exponent is low, then an unnatural shine is produced.

* The Blinn-Phong model is the same, but uses a halfway vector
between the view direction and light direction to calculate 
the specular value. This ensures that there will be no instance
where the angle between the halfway vector and normal exceeds 90 deg.
